# Provider access register

Generated by `node tools/acceptance/provider-access.mjs` from `src/provider-access.json`, the program registries
(`src/conditional-programs.ts`, `src/discovery-programs.ts`) and the provider acceptance ledger
(`src/acceptance-ledger.json`). Do not edit it by hand (ACC-05).

It records, per provider, what the deployment holds as the owner declares it, each declaration with its date, the
programs that gate the provider, and what owner-authorized live acceptance has recorded. A declaration is a
statement, never a grant: AMCP still sends every request under every control, and the provider decides. AMCP never
infers a cause from a refusal (a 403 stays `PROVIDER_ACCESS_DENIED` unless the provider names its code). The owner
health view on Settings shows the same declarations live, beside each connected provider’s last successful sync, last
sync refusal code and latest program observation.

## Updating a declaration

1. Edit the provider’s approval in `src/provider-access.json`: `status` is `approved`, `applied`, `denied` or
   `not_needed` (or `undeclared`), `value` is a short level such as `Standard` (or `null`), and `declared_at` is the
   day of the declaration. Never write a token, key, account or customer ID or e-mail address; the register refuses
   them. Approval e-mails and tickets stay in the owner’s private evidence store.
2. Run `npm run build`, then `node tools/acceptance/provider-access.mjs`, and commit both files.
3. A declaration is confirmed again by its review date, 90 days after it was made; the owner health view marks it stale after that.

Live acceptance results enter through the ledger, never by hand: each harness in `tools/acceptance/` writes a record
whose rows `node tools/acceptance/ledger.mjs add <record.json>` validates and appends ([acceptance
runbooks](acceptance/README.md)).

For the LinkedIn Media Planning and Audience Insights products and the Display & Video 360 user profile, an
owner-authorized recheck (`tools/acceptance/program-recheck.mjs`, [provider programs](acceptance/PROVIDER-PROGRAMS.md))
prints the dated value to declare: the literal provider code of each refusal, or that the read was observed (ACC-08).

Prerequisites: The connected LinkedIn member needs a role on the ad account in Campaign Manager; LinkedIn must provision this private product for the application; the program reference describes how. Prerequisites: The connected LinkedIn member needs a role on the ad account in Campaign Manager; LinkedIn must provision this private product for the application; the program reference describes how. [Reference](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads/advertising-targeting/audience-insights-api?view=li-lms-2026-09), read 2026-10-06.
- **LinkedIn Lead Sync** (`program:linkedin_lead_sync`, discovery only, no request). The Lead Sync page states that the Lead Sync API is a separate program with its own permission. Prerequisites: LinkedIn must approve the application for the Lead Sync API, which is a separate program from the Advertising API; The connected member must grant r_marketing_leadgen_automation, which AMCP does not request today; Lead responses are personal data: reading them also needs the personal-data policy to open LinkedIn leads. [Reference](https://learn.microsoft.com/en-us/linkedin/marketing/lead-sync/leadsync?view=li-lms-2026-09), read 2026-10-08.
- **LinkedIn Matched Audiences** (`program:linkedin_matched_audiences`, discovery only, no request). rw_dmp_segments belongs to the Audiences program and is not granted automatically with the LinkedIn Marketing API Program. Prerequisites: LinkedIn must approve the application for the Audiences program; it is not granted with the Marketing API; The connected member must grant rw_dmp_segments, which AMCP does not request today. [Reference](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads/advertising-targeting/create-and-manage-segments?view=li-lms-2026-09), read 2026-09-30.
- **LinkedIn saved media plans** (`program:linkedin_media_plans`, discovery only, no request). rw_media_plans belongs to the Media Planning API program and is not granted automatically with the LinkedIn Marketing API Program. Prerequisites: LinkedIn must provision the Media Planning API product for the application (Advertising API access, an application survey and Technical Sign Off); The connected member must grant rw_media_plans, which AMCP does not request today. [Reference](https://learn.microsoft.com/en-us/linkedin/marketing/media-planning/media-planning-overview?view=li-lms-2026-09), read 2026-10-08.
