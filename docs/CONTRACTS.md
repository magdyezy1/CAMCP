Every local action and delegated enum has a status in [ACTION-CONTRACT-COVERAGE.csv](implementation/ACTION-CONTRACT-COVERAGE.csv), also available through `amcp_workspace contracts`. [VENDOR-METHOD-COVERAGE.json](implementation/VENDOR-METHOD-COVERAGE.json) separately includes every method in the pinned public specifications, including methods missing from the catalog. Generate and check both with `contracts:actions` / `contracts:actions:check`. These inventories preserve blocked operations and never grant execution.

## Evidence and maintenance

Google Ads v23: 171 existing native RPC mappings to the official Discovery document, with nested field/type/enum request validation. Five additional Discovery methods remain outside the captured catalog. Microsoft: six pinned WSDL documents with namespace-aware type declarations, inheritance, restrictions and operation correspondence. SOAP evidence does not establish JSON wire parity. No new operation gains write permission from ingestion.

`amcp_tool_help` returns `amcp_contract`. `amcp_write inspect` and prepare return `contract_evidence`. Errors include a category, owner and remedy. Destructive operations retain existing explicit review and policy controls; there is no new acknowledgement that could imply schema provenance makes a write safe.

`generate:vendor:check`, `generate:wsdl:check` and `contracts:check` are deterministic offline checks. The public-provider workflow separately checks remote schemas and documentation. A changed page is a maintenance signal, not proof of a breaking change. No CI job automatically upgrades versions or submits account mutations.

## google

Maintenance: [official updates](https://developers.google.com/google-ads/api/docs/release-notes). [Lifecycle](https://developers.google.com/google-ads/api/docs/sunset-dates). Documented sunset month 2027-02, checked 2026-09-18.

- v23 uses start_date_time/end_date_time in customer timezone, not start_date/end_date.
- Discovery validates fields; review contracts still restrict mutation families and batch sizes.
- Explorer access needs administrator/provider approval; do not infer a token sunset.

## meta

Maintenance: [official updates](https://developers.facebook.com/documentation/ads-commerce/marketing-api/marketing-api-changelog). [Lifecycle](https://developers.facebook.com/docs/graph-api/changelog/).

- Per-account AMCP write grants are separate from Meta token/Page permissions.
- v25 rejects legacy AUTOMATED_SHOPPING_ADS/SMART_APP_PROMOTION. New campaigns cannot set existing_customer_budget_percentage; advantage state fields are read-only.
- Changelog access can be rate-limited; do not impose unverified blanket creative field bans.

## tiktok

Maintenance: [official updates](https://business-api.tiktok.com/portal/docs).

- Native /ad/create/ uses one creatives[] record in each AMCP review. Smart+ differs.
- Discover an authorized existing identity; identity provisioning remains unqualified.
- Pixel, CTA and format prerequisites depend on the endpoint and objective. Keep large IDs as strings.

## snapchat

Maintenance: [official updates](https://developers.snap.com/marketing-api/Ads-API/changelog).

- Creative collection PUT and JSON Patch have separate native payloads. PATCH was not removed.
- Shared creative edits can affect all attached ads and trigger provider re-review.

## linkedin

Maintenance: [official updates](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/recent-changes).

- Monthly version is pinned across prepare, mutation and read-back.
- Organization DSC requires exact binding, recorded read/write social scopes and matching AVAILABLE media. Provider products and Page roles remain separate.
- PUBLISHED non-feed DSC is content; the later ad creative is created PAUSED.

## x

Maintenance: [official updates](https://docs.x.com/x-ads-api/fundamentals/versioning).

- No fake PAUSED promoted Tweet. Promotion is activation.
- Creative edits may disrupt existing promotions; retain the impact guard and explicit override.
- Register the exact media_key without media_category; upload INIT still uses its category.

## microsoft

Maintenance: [official updates](https://learn.microsoft.com/en-us/advertising/guides/release-notes?view=bingads-13).

- Six WSDLs document SOAP operation/type structure. JSON transport has independent contracts.
- Search writes only; media import remains unsupported.
