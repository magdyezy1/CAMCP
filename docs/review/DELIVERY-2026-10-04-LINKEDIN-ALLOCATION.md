## Result and native contract

The original `linkedin_campaign` daily preset now supports retained allocation candidates and the existing
constrained sensitivity model. Campaign URNs stay exact, including numeric components above JavaScript's safe
integer limit. Original UTC mapping, native analytics collection/request, account currency checks, daily source
period and `externalWebsiteConversions` definition must qualify. Attribution, completeness and conversion
thresholds remain explicit declarations. Imported, different-grain or edited source metadata cannot become a guided
budget draft. The model remains linear sensitivity with explicit floors/caps, not a calibrated delivery forecast.

An explicit `equal_daily` preview selects at most 20 original campaigns. It reads the active account, each
selected campaign and each distinct parent group twice. Current actor, selected login, reporting/write scopes,
account write grant and credential/account/scope configuration are checked around reads. The monthly API version
is fixed in the preview and its native steps. Limits cover 180 actual transport attempts including retries,
100 resource observations, 8 MiB and 60 seconds, with at most 64 KiB per exact resource. The preview retains
bounded request/hash/time references and interpreted native state; credential signatures and credentials are omitted.
These are bracketed observations, not an atomic cross-resource snapshot or complete account inventory.

Only active/paused independent campaign daily budgets qualify. Campaign lifetime budgets, explicit pacing strategies,
shared/dynamic campaign-group optimization, group daily budgets, unknown budget/pacing fields, ambiguous money,
foreign/missing identities, missing campaign versions and incomplete resource responses refuse the guided path.
Existing group total caps are checked and preserved. Statuses, targeting, objectives, schedules and other fields
are not changed by the generated request. This narrow qualification does not assert that every native budget mode
or account objective is supported by the guided workflow.

The [official campaign contract](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads/account-structure/create-and-manage-campaigns?view=li-lms-2026-08)
defines daily amounts as decimal account-currency values, UTC budgeting and daily spending up to 150% when auction
opportunities are strong. The [campaign-group contract](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads/account-structure/create-and-manage-campaign-groups?view=li-lms-2026-08)
distinguishes dynamic shared optimization/group daily budgets from existing total caps. These primary sources
were checked on 2026-10-04. The draft composes the existing account/campaign/group GETs and campaign POST
REST.li `PARTIAL_UPDATE`; no new native action, family, entitlement or OAuth scope is added.

Period allocations divide over reference days using exact six-place integer arithmetic, round down, retain
residuals and refuse a result below an explicit floor. Those integers are local precision, not LinkedIn native
units. Native bodies contain only `{patch:{$set:{dailyBudget:{amount:"<decimal>",currencyCode:"<account currency>"}}}}`
at the original exact account/campaign path. Native minimum budgets and live objective/account acceptance are not
guessed. Daily settings continue until changed and are not hard daily or reference-period spending caps; no end
date or automatic period cap is created.

## Source binding, review and recovery

Previews last 10 minutes and belong to the original actor/session. A tenant can retain at most 100 current
allocation previews. Their cap now uses a SQL count rather than loading every private preview; expired entries
are reclaimed. Confirmation requires the original preview ID/hash. Current source/model allocations, native
campaign/group/account state and actor authority are rechecked before one unapproved draft is created with the
existing transactional binding. A concurrent create is refused as busy; a saved preview returns its original
plan without another native read. New allocation bindings also retain an exact modeled-allocation hash, so
changing retained normalized rows cannot preserve the original proposal while reusing its source metadata.

Unsent prepare/execute checks original arguments, source/model, native campaign and group controls, current
authority and plan revision. Each campaign uses the existing frozen native review, account ownership/write
permission, explicit spending acknowledgement, original idempotency key and receipt read-back. Independent
accepted campaign updates do not invalidate an unchanged next campaign through incidental group telemetry.
Uncertain original execution keeps its original review/key and recovery; it does not rerun source selection
or create a replacement mutation. Preview/save/candidate/model calls send no provider mutation.
