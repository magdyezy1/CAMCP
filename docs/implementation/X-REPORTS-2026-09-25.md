# X asynchronous analytics — 2026-09-25

This is an implemented native job lifecycle, with synthetic qualification. It
does not complete the whole X Ads API or replace the reporting dashboard source.

## Journey and boundaries

- Prepare and inspect the exact query-only POST using amcp_write. Re-read account
  currency, timezone, entity ownership and original OAuth 1 identity before submit.
  Retain the immutable review and durable original-key claim.
- Store a validated provider job ID and its definition before any late
  authorization denial. A valid failed receipt remains failed and inspectable.
  Processing and uncertain submissions share the account's 100-slot admission
  record across workspaces/workers. Observed terminal jobs release their slots.
- Poll exact original job IDs on the original connection. No arbitrary job access
  or automatic new submission. Status does not certify downloaded report rows.
- Download only a fresh bound SUCCESS URL, on the documented host/job path,
  without advertising credentials. Pin public DNS answers into TLS; reject
  redirects, private addresses, malformed length, corrupt gzip and invalid UTF-8.
- Validate original definition, account, unique requested entities, segment grain,
  time-series length and finite native metrics. Missing entities remain incomplete.
  Never aggregate currencies, placements or incompatible attribution implicitly.
- Cache encrypted results for up to six hours/native expiry; retain original-job
  bindings for 30 days. Every cached read still checks current authority and job
  status. Two global transfer/cache slots and job leases bound concurrent memory.
  These are additive document kinds, with no SQL schema migration.

## Limits and operational consequences

AMCP bounds prerequisites to 48 reads/60 seconds/8 MiB. Download bounds are 30
seconds within the operation's 60-second monotonic deadline, 8 MiB compressed,
32 MiB expanded, 25,000 segments, one million metric cells, and 512 KiB per page.
There is no automatic splitting that could silently change a requested report.

Unresolved submissions keep admission slots. Without a received ID, there is no
documented unique native request key for safely identifying and adopting a job.
Operators must reconcile those cases; clearing the quota manually is not a
supported automatic recovery path. Local admission does not know jobs created
outside AMCP and does not replace native rate limits. Processing state is checked
only when polled/verified; unused completed jobs can conservatively hold slots.

Cancellation's captured DELETE route lacks a current verified native contract.
The platform filter, legacy result-host/path variants, dashboard backfill and
scheduled asynchronous synchronization remain separate qualification work. Their
absence is explicit, not hidden by family-level support.

Rollback to earlier code must preserve reviews, idempotency claims and job
documents. Earlier binaries cannot retrieve these jobs; do not recreate them.
Re-enable the current build to recover original IDs. No credential migration,
new dependency, deployment configuration or provider permissions are required.

## Evidence and acceptance

`tests/x-report-jobs.test.ts` covers create/pending/status/download/replay,
shared admission, immutable definitions, zero-budget policy behavior, all six
entity types and six segmentations, exact strings for large IDs, DST,
tenant/account/login binding, in-flight withdrawal, unknown outcomes, restart,
encrypted cache, leases, malformed/partial native output and archive/URL limits.
The guide's submission and result-read examples are compiled without credentials.

Logs are retained under `.runtime/contract-completion-20260924/`; the continuation
checkpoint records first failures and follow-ups. No synthetic result establishes
provider approval, exact account eligibility, MACT access, real CDN behavior,
weighted Ads API quotas or live report reconciliation. Required future evidence:
a credential-authorized isolated account job, native status progression, gzip
download and numerical comparison with the matching Ads UI definition.
