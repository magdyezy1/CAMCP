# DV360 YouTube video ad assets and Demand Gen exclusions — 2026-09-27

Base revision: `1d90531` on `Codex-branch`, working copy `Downloads/CLaude workspace`.
Push target: `magdyezy1/CAMCP` only. No live provider calls, credentials, permissions,
deployment or DNS changes were made. All evidence below is synthetic.

Why: Demand Gen ads reference ad assets by ID. YouTube video assets were blocked, so a Demand Gen
video ad could not be prepared. A DV360 help page read after the targeting batch (`1d90531`)
also showed that Demand Gen only excludes keywords, categories and placements.

Contract source: the pinned Display & Video 360 API v4 Discovery document (`AdAsset`,
`adAssets.create`, `bulkCreate`, `get` and `list`), [Create ad assets](https://developers.google.com/display-video/api/guides/tasks/serve-demand-gen-ad/create-ad-assets)
and the DV360 Help article [Create a Demand Gen line item](https://support.google.com/displayvideo/answer/15598924),
read on 2026-09-27. Key facts:

- `create` and `bulkCreate` accept only YouTube video assets (`youtubeVideoAsset.youtubeVideoId`);
  image assets are uploaded as media, and `get` and `list` return only YouTube video assets.
- An optional `syntheticContentAttestationStatus` labels assets made or edited with AI.
- The list filter supports `youtubeVideoAsset.youtubeVideoId`.
- "Positive targeting of keywords, categories or placements is not available for Demand Gen line
  items. Exclusions are supported."

## Change

New reviewed family `dv360_ad_assets` (`src/dv360-ad-assets.ts`):

| Part | Behaviour |
|---|---|
| Request | `{adAsset}` or `{adAssets}` (1–25): YouTube video type, an 11-character video ID, optional attestation; each video once; no output-only fields (the pinned model refuses them) |
| State | One filtered list read per video |
| Checks | A video that is already an active asset is refused with the asset to reuse; archived ones may be created again |
| Safety | No spending effect: no confirmation, not an activation |
| Receipt | The created assets, one per video, of the YouTube type |
| Verification | Each new asset read by ID: type, video and attestation |

The generic DV360 state check, which verification also runs, now knows that an `adAssets` path
names an `adAssetId`; without it, verification of an asset read reported a target mismatch. The
first test run showed this.

Demand Gen targeting (`src/dv360-line-item-targeting.ts`) now refuses positive keyword, category,
URL, app, app category, YouTube channel and YouTube video targeting on Demand Gen line items and
ad groups; exclusions (`negative: true`) remain qualified.

Other code: `src/write-review.ts`, `src/write-verification.ts`, `src/write-impact.ts`,
`src/review-state.ts`, `src/preflight.ts` (assets are exempt from the generic "bid/budget/spend"
heuristic: a random video ID can contain "bid"), `src/reviewed-routes.ts`, `src/types.ts`,
`src/action-contracts.ts` and `src/provider-contracts.ts` (DV360 contract version 8). Guidance:
"Demand Gen ad assets" in `Skills/amcp-campaign-builder/references/dv360-and-measurement.md` and
an executable inspect example.

## Tests

`tests/dv360-ad-assets.test.mjs`, six tests:

1. An asset is created once without spending confirmation and verifies; a replay makes no second write; a video ID containing "bid" and "spend" needs no confirmation.
2. A bulk creation verifies every asset, including an AI attestation, and may reuse a video whose asset is archived.
3. Nine malformed requests fail without network requests (two of them already at the pinned model).
4. A video that is already an active asset is refused with its asset ID.
5. A receipt naming another video or missing an asset is a failure and is not resubmitted; a lost attestation is inconclusive.
6. The methods, filter and model match the pinned Discovery document.

`tests/dv360-ad-group-targeting.test.mjs` gains positive YouTube channel and keyword targeting
refused for Demand Gen, and a keyword exclusion accepted.
