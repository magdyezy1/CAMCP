# Meta Graph API v25.0 → v26.0 (2026-09-28)

Second in the owner's upgrade order (Google Ads first, then LinkedIn and Meta, then Criteo). LinkedIn's API
reference is on a host the review environment's network policy blocks, and LinkedIn publishes no machine-readable
contract, so its upgrade waits. Meta's reference pages are blocked too, but Meta publishes its official Python
Business SDK on GitHub, generated from Meta's API specification and tagged per Graph API version. AMCP already used it
as evidence (the Insights and post fixtures, pinned at 25.0.3), and it is the evidence for this upgrade.

Before moving the two existing extractors to 26.0.2, the rewritten versions were run at 25.0.3: they reproduced the
pinned v25 fixtures byte for byte, which also showed that the downloaded 25.0.3 files carry the hashes pinned in
September.

## What v26.0 changed, per the SDK

| Change | In AMCP |
|---|---|
| 7 requests removed, all commerce order reads (`CommerceMerchantSettings` returns and tax settings; `CommerceOrder` cancellations, items, payments, refunds, shipments) | Not in any AMCP catalog. |
| 4 parameters removed: ad set `cost_bidding_mode` (create and update), `meta_moment_maker_spec` on reach-and-frequency predictions, `bid_spec` on WhatsApp message templates | Not sent by AMCP and not in the catalog's native fields. |
| 23 readable fields removed: 15 ad set fields (`cost_bidding_mode`, `budget_schedule_specs`, `budget_source`, `budget_split_set_id`, `campaign_spec`, `daily_imps`, `date_format`, `execution_options`, `is_sac_cfca_terms_certified`, `line_number`, `rb_prediction_id`, `time_start`, `time_stop`, `topline_id`, `tune_for_category`), four Insights metrics (`marketing_messages_website_add_to_cart`, `…_initiate_checkout`, `…_purchase`, `…_purchase_values`) and four delivery estimate fields | None is in a field list AMCP requests. AMCP already left `execution_options` out of ad set read-back. The Insights test checks every metric AMCP offers against the v26 model. |
| 8 enum values removed, all of removed ad set fields (attribution counting, budget source, cost bidding mode) and one ad volume recommendation type | Not used. |
| Additions: 38 parameters, 43 fields, new enum values (for example `placement_controls_per_objective` on account controls, `creative_audience_pairing_persona` on ads, `is_ai_generated` on video uploads) | Available through the native gateway; reviewed families keep their own allowlists. |

Of the 591 catalog actions, 419 map to an SDK request (the node named by the path, the method and the edge); every one
of them exists at 26.0.2. The other 172 have no SDK counterpart to compare (nodes the SDK does not model, such as value
rule sets, or edges it does not generate). Two rules written against v25.0 still hold at 26.0.2: the campaign
restrictions of `validateMetaCampaign` (the smart promotion types and create parameters are unchanged), and the brand
safety and value rule routes (unchanged apart from one new optional account control).

## What AMCP changed

- `src/meta-version.ts` holds the version (`metaApiVersion`). Paths (`metaPrefix`), route recognition (`metaRoute`, which
  matches the current version only), the Facebook Login dialog and token URLs, the catalog records and captured
  listings follow it.
- 27 modules and the owner's live verification tool take their paths and routes from it instead of `/v25.0/`,
  including account discovery and the two sign-in flows.
- `src/catalog-versions.ts` replaces the Google-only hooks of batch 14: one table says, per gateway sent at a newer
  version than it was captured at, how an action, a captured page or description and the tool definition read at the
  version sent. The registry, introspection, the capture verification and the tests use it.
- `tools/meta-sdk.mjs`: shared SDK reading and parsing for the three Meta evidence tools.
- `AMCP_META_API_VERSION=v25.0` moves every Meta request back without a code change; any other value stops start-up.

## Not verified

- Behaviour. The SDK describes requests, fields and values, not behaviour, defaults or deprecation schedules; Meta's
  v26.0 changelog could not be read. Reviewed writes still read state back and verify it after every change.
- v25.0's end date (F-52 recorded it as unverified; it remains so).
- Live acceptance: all tests use synthetic accounts. No request was sent to Meta.

## Doing this again for the next version

1. Download the adobjects modules of the new SDK release and of the current one (the modules named in
   `tests/fixtures/meta-sdk-changes-v26.json`, or crawl the imports from the catalog's node types).
2. Set `metaVersion` / `metaSdkTag` in `tools/meta-sdk.mjs`, the default and accepted versions in
   `src/meta-version.ts`, and the `from` release in `tools/meta-sdk-changes.mjs`.
3. Run the three evidence tools and read the removals; handle every one AMCP sends or reads.
4. Run `tests/meta-version.test.mjs`, the Meta suites and every generated-artifact check.
