# Criteo Retail Media 2026-01 → 2026-07: upgrade (2026-09-29)

AMCP now sends every Criteo Retail Media request to API 2026-07. This carries out the plan in
[the preparation record](CRITEO-2026-07-PREPARATION.md), using Criteo's official documents.

## Evidence

- The official 2026-07 OpenAPI document, `https://api.criteo.com/2026-07/retailmedia/open-api-specifications.json`,
  pinned as `.mirror/VENDOR/criteo-retail-2026-07.json` by `tools/fetch-vendor-specs.mjs` (sealed by its SHA-256,
  like every pin). It replaces the 2026-01 pin. The request routes, schemas and response checks come from it.
- Criteo's guides, read 2026-09-29: the changelog (2026.07 breaking changes), the Versioning Policy, the Demand Side
  Analytics overview, the Performance Report and "Migrating from the Legacy Reporting API". Criteo serves the current
  version's guides without a version in the path; `src/criteo-version.ts` links them through `criteoDocs`.

## What changed for AMCP (official 2026-01 compared with official 2026-07)

Each operation behind AMCP's 108 Criteo actions was compared with references resolved and descriptions and
examples left out.

| Change | Actions | What AMCP does |
|---|---|---|
| Unchanged | 97 | Path version only. |
| The account, campaign and line item reports removed; one performance report, scoped by exactly one of `filters.accountIds`, `campaignIds` or `lineItemIds` | `GENERATE_ASYNC_ACCOUNTS_REPORT`, `…CAMPAIGNS…`, `…LINE_ITEMS…` | All three send to `POST /reports/performance` (`GenerateAsyncPerformanceReport`), as Criteo's migration guide maps them. The report family (`src/criteo-report-jobs.ts`) checks the new request: the scope list matching the action, optional filter lists, the renamed dimensions, match levels, and 100 days for every scope. |
| Balance list replaced by `GetPageOfBalancesV1`: `limit-to-id`, `offset` and `limit`; metadata `count`, `offset` and `limit`; lowercase `spendType` | `GET_BALANCES_BY_ACCOUNT_ID` | The campaign family's balance read (`src/criteo-campaign-writes.ts`) uses the new query and checks the new page; a standard balance's `spendType` is `onsite`. |
| Campaign append and delete on a balance replaced by V1 operations (path parameter `balanceId`, body `data` object) | `APPEND_CAMPAIGNS_BY_BALANCE_ID`, `DELETE_CAMPAIGNS_BY_BALANCE_ID` | Blocked writes; aliases bind them to the V1 operations. |
| Balance history replaced by `GetBalanceHistoryV1` (limit up to 500, rows under `attributes`, camelCase change types) | `GET_BALANCE_HISTORY` | Native read; alias. |
| Balance modify replaced by `UpdateBalanceV1` (`retailerPoNumber`, `endDate` wrapper) | `MODIFY_BALANCE_BY_ACCOUNT_AND_BALANCE_ID` | Blocked write; alias. |
| `poNumber` renamed `retailerPoNumber` | `CreateBalanceByAccountId`, `AddFundsByAccountAndBalanceId` | Blocked writes; schema only. |
| Retailer search: `isAvailable` removed, `budgetModelAvailabilities` and the `aiAssistant` page type added | `SearchAccountRetailers` | The audience segment family reads retailer identity only, which is unchanged. |

Eight captured action names no longer equal an operation ID; `criteoAliases` in `tools/fetch-vendor-specs.mjs` binds
each to the operation Criteo's changelog names as its replacement. Every captured action binds (no gaps). Nine
2026-07 operations have no captured action and stay unexposed: the single-balance read, store inventory upsert and
delete, the missed-opportunities and attributed-transactions reports, and the four synchronous reports.

The report row limit moved to 10,000,000 rows; `CRITEO_REPORT_INCOMPLETE` now uses it, and a report above AMCP's own
25,000-row retrieval limit gets `CRITEO_REPORT_TOO_LARGE`.

## Version end

Criteo supports each version for 12 months. 2026-07 was released in July 2026, so its support can end from 2027-07
(`src/provider-sunsets.ts`, basis `policy`). 2026-01 is supported until 2027-01-27 (Versioning Policy).

## Compatibility and rollback

- The action names, arguments other than the report payload, and every family's checks are unchanged. Report
  payloads change shape (see `Skills/amcp-campaign-builder/references/criteo.md`); a 2026-01 report payload is
  refused before any request.
- Report jobs submitted before the upgrade cannot be read through their old review (its request is a 2026-01
  report). Review a new report.
- There is no switch back to 2026-01: its report and balance shapes differ. Rollback is reverting this change.
