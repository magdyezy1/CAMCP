# Google Ads v23 → v25 (2026-09-28)

The owner decided on 2026-09-28 to upgrade the provider APIs, Google Ads first. AMCP now sends every Google Ads request
at **v25** and checks it against the pinned v25 contract. This records what was compared, what changed, what AMCP
changed in response, and what could not be checked.

review environment's network policy, so nothing here relies on them.

## What v25 changed, as it affects AMCP

Method and schema comparison of the two Discovery documents, and a comparison of the protobuf descriptors behind
AMCP's legacy action names (regenerated for both versions by the same tool):

| Change | Effect in AMCP |
|---|---|
| Two methods removed: customer and campaign lifecycle goal configuration | The two native RPCs and `CONFIGURE_CUSTOMER_LIFECYCLE_GOAL` / `CONFIGURE_CAMPAIGN_LIFECYCLE_GOAL` are refused as `PROVIDER_ACTION_UNSUPPORTED`. |
| Lifecycle goal rows removed from GAQL (`customer_lifecycle_goal`, `campaign_lifecycle_goal`) | `LIST_CUSTOMER_LIFECYCLE_GOALS` / `LIST_CAMPAIGN_LIFECYCLE_GOALS` are refused; the refusal names `FROM goal` and `FROM campaign_goal_config`. |
| `Goal` and `CampaignGoalConfig` gained `NEW_CUSTOMER_ACQUISITION` and `LOYALTY_RETENTION` | The lifecycle refusals name these as the replacement. AMCP has no reviewed family for goal writes yet (F-80). |
| One method added: Smart campaign Performance Max draft generation | Not in the captured catalog, so not exposed. |
| Shareable previews: the list moved into `operation`, an asset group is named by resource, `previewType` is required, and the result is `result.previews` (one row per preview, naming its target) with no per-preview errors | `src/google-preview-writes.ts` rewritten for the new request and result; the `amcp_ad_previews` Google call, the guide and examples updated. A request in the v23 shape is refused, and the error's `version_change` shows the v25 one. |
| `Campaign.video_brand_safety_suitability` removed (the account-level field remains) | `SET_CAMPAIGN_BRAND_SAFETY` is refused, naming the reviewed customer change and `SET_CAMPAIGN_CONTENT_LABEL_EXCLUSIONS`. |
| `UserListCustomerTypeCategory.LOYALTY_SIGN_UPS` removed | Removed from the user list customer type family. |
| 19 other fields removed, all in keyword and reach forecasting, incentives, creator insights and Local Services lead contacts (in `CampaignToForecast`, `ForecastAdGroup`, `KeywordForecastMetrics`, `GenerateReachForecastRequest`, `Targeting`, `PlannableTargeting`, `FetchIncentiveRequest`, `Incentive`, `IncentiveOffer`, `GenerateCreatorInsightsRequest`, `YouTubeMetrics`, `ContactDetails`) | No AMCP code sends or reads them; a request naming one is refused by both the Discovery check and the legacy descriptor check. |
| Now required: `VideoResponsiveAdInfo` videos, logo images and business name; `DemandGenVideoResponsiveAdInfo` videos and logo images; both `ApplyIncentiveRequest` fields | The legacy descriptor check enforces them. |
| 116 descriptors and 234 fields added; 16 enums gained values (for example 10 conversion action types and one category) | Available through the native gateway; reviewed families keep their own allowlists. |

Everything else AMCP depends on is unchanged, and tests show it:

- Every one of the 169 captured RPCs v25 still has maps to exactly one v25 method, with its request schema.
- Every request field the catalog requires exists in the v25 request or its query parameters (152 checked). One was
  renamed (`shareable_previews` → `operation`), mapped in `src/google-version.ts`.
- All 626 GAQL fields AMCP took from the v23 field reference exist in v25 with the same cardinality. (Selectability
  stays as the v23 reference recorded it; Discovery does not carry it.)
- The proto evidence of user access and portfolios is identical apart from the route version; conversion actions
  gained enum values and lost none.

## What AMCP changed

- `src/google-version.ts`: the one place the version lives (`googleAdsVersion`); paths, the Discovery contract key,
  the catalog records, the tool definition and captured listings follow it. Action names keep their captured
  `google_ads_v23_…` spelling: callers use them as names.
- 38 source modules build paths from it instead of `/v23/`, including two server paths that were outside the catalog
  and would have broken account discovery and re-authorisation at v23's sunset (F-77).
- `tools/google-legacy-descriptors.mjs`: a generator for the legacy adapter's descriptors. It reproduces the pinned v23
  set exactly (2,206 descriptors, 726 sources, 171 request types) before producing v25 (2,297, 756, 169) (F-78).
- `tools/google-protos.mjs`: shared by the four proto evidence tools (reading, message extraction, pinning).
- The conversion action GAQL field table moved to its own fixture (`google-conversion-fields-v23.json`), like the
  others, so the proto part can follow the version.
- A missing required Google field is the caller's `MISSING_PARAMETER`, not `INTERNAL_ERROR` (F-79).
- Contract ledger: 7 Google rows became `provider_unsupported` (reviewed 213 → 212, blocked 57 → 53, reads 175 → 173).

## Not verified

- v25's sunset month: the sunset page could not be read. `sunset_month` in `src/contract-evidence.ts` still records
  v23's (2027-02), the earlier of the two, so any reminder built on it comes early rather than late.
- Live acceptance: all tests use synthetic accounts. No request was sent to Google.

## Doing this again for the next version

1. Set `googleAdsVersion` (`src/google-version.ts`) and `googleVersion` (`tools/google-protos.mjs`); the version test
   fails until both agree.
2. Fetch and pin the new Discovery document (`tools/fetch-vendor-specs.mjs`), then regenerate the vendor routes.
3. Download the new protos (the import closure of the services in `googleProto.sources`) and run
   `tools/google-legacy-descriptors.mjs --source-dir <dir> --write`, then the four evidence tools.
4. Compare the methods, request schemas and descriptors of the two versions, as above. Retire removed methods and
   aliases in `src/retired-provider-actions.ts`, map renamed required fields in `src/google-version.ts`, and update the
   reviewed families whose fields changed.
5. Confirm no request sends the `developer-token` header. Google sunset developer tokens on 2026-09-09 and will
   reject the header in a future major version; since PRV-04 (2026-10-09) `src/transport.ts` never sends it and
   `googleDeveloperTokenWarning` (`src/google-version.ts`) warns at startup and in owner health while
   `AMCP_GOOGLE_DEVELOPER_TOKEN` is set. Remove the variable from the deployment before upgrading (owner action), and
   check the new version's release notes for any other request header it stops accepting.
6. Record any dated change inside the new version (an enum value, header or field) in `src/provider-deprecations.ts`
   with its effective date and source, and add the new version's entry to `src/provider-sunsets.ts`.
7. Run `tests/google-version.test.mjs`, the Google suites and every generated-artifact check.

## Superseded by later work (recorded 2026-10-22)

This record keeps the words of 2026-09-28. Three of its statements no longer hold:

- **Goal writes.** "AMCP has no reviewed family for goal writes yet (F-80)" is superseded: the reviewed families
  `google_lifecycle_goals` (`src/google-lifecycle-goals.ts`: v25 goals and campaign goal configs, the replacement for
  the removed lifecycle goal configuration) and `google_conversion_goals` (`src/google-conversion-goals.ts`) are
  registered.
- **v25's sunset.** "Not verified: v25's sunset month" is superseded: `src/provider-sunsets.ts` records v25 as ending
  in 2027-08 from Google's published "Sunset dates" timetable (`basis: official`, checked 2026-09-29), with v23's
  2027-02 kept only in its note.
- **Developer tokens.** Google sunset developer tokens on 2026-09-09: API access belongs to the Google Cloud project of
  the OAuth client, and since PRV-04 (2026-10-09) AMCP never sends the header (step 5 above). The Google trap in
  `src/contract-evidence.ts` (shown in [contracts](../CONTRACTS.md)) says so since 2026-10-22; it had said not to
  infer a token sunset.
