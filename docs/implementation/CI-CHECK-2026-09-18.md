# CI action-ledger failure and correction

Base revision: `8b626f13a52c98f781215007713117adb3fea135`, branch `Codex-branch`.
Only `tools/action-contracts.ts`, the new artifact regression tests, and this record
are changed. Application CSV exports and provider execution contracts are unchanged.

## Confirmed cause

The supplied Linux CI log reports 639 passing tests, no skipped tests, four passing
capture tests, and then failure in `contracts:actions:check`:
`Action contract ledger is stale: docs/implementation/ACTION-CONTRACT-COVERAGE.csv`.
The generator emitted CRLF while `.gitattributes` requires LF for text. Its exact
comparison therefore rejected Git's normalized checkout, even though the locally
generated file passed before committing.

The original working CSV contained 1,356,621 bytes and 3,224 CRLF sequences. The Git
blob contained 1,353,397 bytes and no CRLF sequences. Normalizing the working file
to LF produced exactly the committed bytes. This was a generator defect, not stale
action metadata or a provider failure.

## Correction and regression

The source-controlled CSV generator now emits LF. The byte-for-byte stale-content
check remains unchanged. Regeneration produces exactly the existing committed CSV;
no action rows or artifact data changed.

`tests/action-contract-artifacts.test.ts` runs the real compiled CLI against a new
temporary output directory and copies only public pinned vendor JSON inputs. It
normalizes all three artifacts as Git does, checks them, and verifies repeatable
generation. A second test changes a real action in the CSV and then removes the
file; both checks must fail without rewriting the changed or missing artifact.
It uses no live provider calls, credentials or historical account samples.
