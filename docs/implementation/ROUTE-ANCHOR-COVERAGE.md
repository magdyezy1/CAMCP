# Route anchor coverage

Generated by `npm run contracts:actions` (`tools/route-anchors.ts`) from the action ledger, the pinned vendor documents and SDK evidence, and the captured catalog; `npm run contracts:actions:check` fails when it is stale. Do not edit it by hand (ARC-03).

anchor_status says what the method and path of each action rest on: vendor_spec, sdk_method and documented_url name a pinned vendor document, a pinned SDK request or a dated documentation page; captured_only rests on the frozen captured catalog alone and names its capture file; unanchored gives its reason. A native_read that is not anchored carries the advisory read_unanchored. Anchors are evidence only: they never enable, block or reclassify an action.

## Adding an anchor

Pin the vendor document (`tools/fetch-vendor-specs.mjs`) or SDK evidence, or record a page in `tools/route-anchor-documents.json` with the exact method and path it documents, the page URL, the date it was read and a note. The generator refuses an entry whose method and path no longer match its route. Then run `npm run contracts:actions` and review the difference.
