# V2 round 2 compatible dependency remediation of 2026-11-04

This separate change follows the independently qualified SDK foundation (`3b950b2d`, record `9d94bf81`). It addresses
existing advisory findings before Round 2 publication. Qualification of this patch is in progress; no push, deployment
or live provider acceptance is claimed. The SDK package versions remain unchanged.

locked nested dependencies were checked through the lock delta. The accepted SDK dependency folder is preserved.
The supply-chain skill is unavailable, so this is a manual review rather than a claimed skill execution.

## Reproduced failures and checks

An isolated Express fixture reproduced the unpatched process exit after a valid gzip frame followed by a corrupt
trailer. The other failing checks showed an incorrectly trusted mapped-IPv6 subnet and 10,000 element validations on
an already oversized constrained array. The same tests pass after patching. A delayed deflate-body compatibility
case also passes. These are synthetic local fixtures, not attempts against a deployed service.

| Check | Result |

| Same regression cases after patch | 4/4 pass, no skips |

| MCP/OAuth/HTTP/stdio and security cases | 48/48 pass, zero skips, 10,907 ms |

The decoder cleanup addresses [body-parser's compressed-body advisory](https://github.com/advisories/GHSA-27r3-jxmh-p828).
The proxy trust guard addresses [mapped-subnet trust](https://github.com/advisories/GHSA-jqcg-44mw-7w3h), and the collection
check addresses [oversized constrained validation](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5). Additional compatible
patches cover query coercion, URI normalization, static-path handling and IPv6 zone parsing.

## Remaining advisory scope

The production-lock audit falls from 15 affected-package entries (12 moderate, two high, one critical) to eight moderate
entries, with no high or critical entries. This describes the advisory database result, not absence of vulnerabilities.
The eight remaining entries share the minimatch dependency chain through ExcelJS/archiver/glob/readdir-glob/rimraf/
zip-stream. The [published trigger](https://github.com/advisories/GHSA-g3hv-75wg-m249) requires attacker-controlled glob
patterns and preprocessing optimization. AMCP exposes no such glob-pattern route; its workbook ZIP entries are
generated by the application. The named optimizer is absent in the installed older minimatch implementations.
No path to the reported trigger was found in the reviewed calls. The raw audit remains; no unsupported major override
or audit suppression is used to force a clean result.

The complete Round 2 closing gates must use the patched dependency graph after all feature packages. This record does
not extend the SDK-only browser/container qualification to different dependencies or establish production readiness.
Live deployment, provider/OAuth reads and actual Sheets exports remain owner-deferred.

The lockfile is normalized to repository LF line endings before the full gate; its parsed graph is unchanged. This
changes the package fingerprint from the earlier preflight's metadata bytes, so full qualification uses a fresh
candidate assembled after normalization.
