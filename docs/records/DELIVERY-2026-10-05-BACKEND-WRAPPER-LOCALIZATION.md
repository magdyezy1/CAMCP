## Bounded language loading

The old decoded-character limit did not bound received UTF-8 bytes. The completed catalog
also exceeds the old one-MiB public diagnostic ceiling. The browser reader and public Arabic
diagnostic ceiling now use 2,097,152 received/decompressed bytes, while the maintained locale
gate refuses a source file above that same UTF-8 budget. The liveness/About byte limits and
all three credential-free public diagnostic routes remain exact; no new automatic network
check is introduced. The interface always fetches the fixed local Arabic asset with original
same-origin credentials/no-cache behavior, explicit redirect refusal and an abort signal.

Streaming fatal UTF-8 decoding supports multibyte sequences split across chunks and refuses
invalid/truncated bytes. Each fetch/read owns one temporary abort listener, removed after
settlement; positive chunks have no arbitrary count cap. A 15-second timer and monotonic
checks bound headers, body reads and immediate-chunk/parse processing; 65 consecutive empty
chunks fail rather than accumulating unbounded empty reads. Cancellation is initiated and
locks/timers are released without awaiting a potentially hanging cancel promise. Refused
HTTP bodies are cancelled without being read. Existing JSON/object/string/placeholder/HTML
validation, coalescing, success caching, failed-cache removal and current-view retention stay
intact. This is bounded application behavior, not a network bandwidth or full browser memory
guarantee. Runtime/provider authorization and native requests are unchanged.

Implementation follows the [WHATWG stream reader lifecycle](https://streams.spec.whatwg.org/#default-reader-release-lock),
[fatal streaming decoding](https://encoding.spec.whatwg.org/#interface-textdecoder) and
[fetch abort behavior](https://fetch.spec.whatwg.org/#abort-fetch). The byte/deadline/empty
budgets are AMCP policy choices qualified by the local regressions below.
