# Brand kit v1: the new AMCP logo, 2026-11-07

On 2026-11-07 the owner supplied a folder, `AMCP_Brand_Kit_v1`, and asked for its logo to be put on the website. The
instruction, with the local path left out: "there is a new folder … AMCP_Brand_Kit_v1, containts the new brand logo
please implement it". The name AMCP did not change. The kit's palette comes from `web/tokens.css` and its own token file
says it is not a replacement for it, so no token, font or colour changed.

This replaces the earlier rule that `web/mark.svg` stays byte-identical to the previous mark, and the pin of its sha256
in `tests/brand-mark.test.mjs` (V2-WEB-01; [the wave 5 target](WAVE5-INDEPENDENT-TARGET.md) and the wave 5 brief state
that rule). The new rule: every logo file the site serves is byte-identical to the kit's. A logo file is never edited,
redrawn, traced, recoloured, cropped or re-exported; a later kit replaces these files whole, together with the pin table.

## Where each file is used

- **The lockup** (`logo-ink.svg` and `logo-white.svg`, 174 by 36 pixels) replaces every pair of the mark and the plain
  text AMCP: the public navigation and sign-in header, the workspace sidebar, the connection result header, the About
  header, and the header of Privacy, Terms, Data deletion and the not-found page in both languages. The footers of the
  landing page and About use the minimum width, 160 by 33 pixels. The brand guidelines say not to replace the outlined
  logo letters with plain type, so the mark no longer sits beside plain text anywhere
  (`tests/brand-lockup.test.mjs` reads every `.brand` and `.about-brand` element). Its accessible name stays AMCP, from the
  image's alt text or the link's existing label (`AMCP home` on About); the name stays in Latin letters on the Arabic
  pages and the art is never mirrored.
- **Variants.** Every lockup holds both images and CSS shows the one that suits the surface: Ink on light, White on dark.
  `theme.js` sets `data-theme` before the stylesheets load, so the right variant shows from first paint. Without
  JavaScript, a dark system gets White through `prefers-color-scheme`. The sidebar and the connection result header sit on
  `--surface-inverse`, which neither theme changes, so they carry White only. Print shows Ink, or nothing: the theme rules
  sit in `@media screen`, so print falls back to the base rule. The rules are in `accessibility.css` (the workspace and
  About, where it loads last) and `privacy.css` (the policy pages, which do not load it). They are not in `about.css`,
  which `tests/web-route-bytes.test.mjs` requires to hold no `data-theme` rule, nor in `theme.css`, the dark layer other
  tests analyse.
- **The icon alone** (`mark.svg`, the dark rounded tile) stays where a square icon is wanted: the About art card (74
  pixels), the landing page's floating chip (34 pixels) and the workspace loader (48 pixels). Nothing relies on the
  previous file's 64-unit tile or its apricot dot. No layout needed the icon-alone fallback: the lockup fits at 320, 375,
  768 and 1280 pixels in both languages and both themes.
- **Browser and device icons.** Every page links `/assets/favicon.ico`, which `publicAssets.html()` versions.
  `/favicon.ico` still answers with a no-cache 302 to the versioned file, now `favicon.ico`; `/apple-touch-icon.png` does
  the same, so iOS finds it without markup. Both are public without a session. `server/public-assets.ts` needed no change:
  it already reads every snapshot file as bytes, rewrites only stylesheets, compresses only text types and takes the type
  from the extension (`image/vnd.microsoft.icon`, `image/png`).

## Logo rules from the guidelines, and how each is held

- **Clear space of half the icon's height on every side.** At 36 pixels tall the ribbon is 28.6 pixels, so 14.3 pixels,
  of which the file's own padding gives 3.6 to 4.4. Eleven pixels outside the image box is enough; the rendered check
  asks for `ceil(0.2985 × height)`. The note under the sidebar lockup moved out of the link and 12 pixels below it, and
  the sign-in header's wrapped row gap went from 10 to 12 pixels (one pixel short of the clear space at 320 pixels).
- **At least 160 pixels wide**; the icon alone at 24 pixels or more. Checked on every page and in the opened phone drawer.
- **Not stretched, rotated, recoloured or mirrored.** No stylesheet sets a lockup's width without `height: auto`, a fixed
  height, a transform, a filter or a mask; the 33 and 30 pixel squares the old mark had are gone.
- **Ink on light backgrounds, white on dark ones.** The rendered check measures the wordmark's contrast against what is
  painted behind the image (4.5:1 or more).

`tools/browser-brand.mjs` is the in-browser check and `tests/browser-brand.test.mjs` its unit test. `tools/browser-workflow-qa.mjs`
runs it for every page of the empty workspace in both languages and both themes (including the opened phone drawer and
print), for the not-found page, and for About, Privacy and the not-found page read without JavaScript.

## Not used, and why

- `AMCP_Primary_Dark` and `AMCP_Primary_Light` carry their own background rectangle, which would show as a box on the
  site's surfaces. The transparent lockup is the same artwork without the box. (The kit's README suggests the primary files
  for the sign-in hero and the header.)
- The monochrome, Iris and Light icons: nothing needs them.
- The `android-chrome` PNGs: the site has no web manifest and this change adds none.
- The social images: the site has no `og:` tags and this change adds none.
- `AMCP_Brand_Tokens.css`: the app's tokens stay in `web/tokens.css`.

## The kit's own caveats

- The vector files are a traced rendition of generated artwork: "a carefully traced rendition of the selected generated
  art; it is not the commercial font file or a pixel-perfect recovered original design file." The wordmark letters are
  outlined paths, with no font file.
- The kit says formal mark registration requires independent trademark clearance. No clearance search was done in this
  change.
- The kit's README says no repository or live website was modified to create the assets. This change commits the five
  files above to a local branch; nothing has been pushed or deployed.

## Limits

- Forced colours are not handled. In a forced-colour theme the browser replaces the sidebar's dark panel, so a White
  lockup there can have no contrast, and a person who picks the opposite theme in AMCP's Appearance control gets the
  variant that theme names, not the one the forced canvas needs. Logotypes are exempt from the WCAG contrast
  requirements. Handling it would need both variants in the sidebar and two more media queries.
- The art is a trace and was not corrected. At 1, 2 and 3 times device scale the lockup and the icon look clean at every
  size the site uses; at 6 times the curves of the C and the P show faint facets. No page was found where the trace looks
  rough.
