## Native evidence and limits

The existing amcp_workspace catalog_compare accepts optional inspect_other_listed_products:
boolean and absent_source_policy: retain. Explicit true is qualified for the existing X
destination only. A nonboolean flag, another absence policy or inspection on an unsupported
destination refuses before native reads. These arguments on another workspace action refuse
before reading or creating an artifact. Omission preserves the ordinary supplied-only comparison.
No native action, reviewed family, dependency or deployment configuration is added.

The original complete bounded two-scan reader keeps account/login/catalog ownership checks
before and after collection, exact uncoerced retailer IDs and native product keys, complete
promotable-user and catalog pages, original pagination and time/byte/attempt budgets, and
the existing 1–50 explicitly selected source products. At most 1,000 listed products can be
returned; an additional row or unfinished cursor refuses without returning a partial proof.

Inspection projects eight supported fields from all listed observations: retailer_id,
product_id, name, original native price string, currency, group_status, item_group_id and
item_group_key. Missing, malformed or unsupported optional values remain null/unknown. The
existing price parser's twelve integer/six decimal digit range is unchanged; no float, FX,
rounding or enlarged native-price interpretation is introduced. Large string keys and accepted
leading-zero prices remain exact. Arbitrary native fields, private markers and URLs are excluded.

Both complete scans must have the same supported material observations, independent of page
ordering. Changes to another listed product's identity, title, accepted price, grouping or
source membership refuse; a fresh explicit read is required. Display order remains the first
scan's original order. These sequential checks do not establish a point-in-time snapshot.

The additional listed_inventory binds original scope, source hash, observation/material hashes,
request reference and capture times. It reports bounded_listed_products, supplied_products_only,
listed_scan_complete true, variant_inventory_complete false, source_absence_established false,
absent_source_policy retain and exact group/selection counts. listed_scan_complete describes
the completed bounded native listing only. Items outside the source selection cannot enter a
draft or removal preview. Existing explicitly selected individual-product removal and original
supplied-product drafts keep their separate review and current-evidence boundaries.

## Primary research

The [official X Ads catalog reference](https://docs.x.com/x-ads-api/catalog-management/reference),
checked 5 October UTC, identifies catalog access as an early-access program. Its product listing
uses count 1–100 and cursor pagination. A grouped product listing returns only the first submitted
variant; native product_key/SKU id and item_group_id/item_group_key have distinct meanings.
Product deletion is permanent and uses product_keys. Consequently, a completed listing plus a
partial source selection cannot prove complete variant inventory or full-store absence and
cannot authorize deletion of another listed product. Actual customer/app entitlement and real
allowed-account acceptance remain unverified. No live X or WooCommerce request is made in this batch.
